# Korean HTML → PDF (weasyprint) with layout verification

Render CJK-rich documents (Korean quiz papers, study guides) to A4 PDF with weasyprint, and **prove the CSS actually applied** with pymupdf. The killer risk: a wrong CSS selector fails *silently* — the document looks plausible in a text dump but a layout rule never applied. Verify with drawn-rect measurements, not by trusting the HTML.

## When to Use
- Building Korean quiz/exam PDFs (multi-choice + answer boxes) from HTML.
- **Prose study guides / textbook-chapter summaries** (`요약`) — use the lighter **Markdown → HTML → PDF** path below, NOT the chunked-HTML quiz pattern.
- Any weasyprint job where CJK text must not break (tofu, CJK-character leaks from source).
- Layout rules you can't visually confirm (box min-height, page-break-inside) need machine verification.

## Pattern B: prose summaries (Markdown → HTML → PDF)
For chapter `요약` documents (headings, prose, tables, formula boxes — **no** multi-choice options or answer boxes), the Markdown path is faster and sidesteps the `write_file` CJK-truncation trap entirely:
1. Write the content straight to a `.md` file (Markdown handles tables, headings, `**핵심**` box via `>` blockquote, code blocks for formula steps). This is the **source of truth** and a durable intermediate artifact — keep it.
2. Convert + render in ONE venv script: `import markdown; body = markdown.markdown(md_text, extensions=['tables','fenced_code'])`, wrap in `<html><head><style>CSS</style></head><body>`+body+`</body></html>`.
3. **Reuse the CSS by copying the `<style>` block from a sibling chapter's existing `요약.html`** (they share one visual identity — blue `#0b3d91` headings, amber `#f6b93b` accent, `Noto Sans CJK KR`). Only change the `@bottom-left` footer label per chapter. Add a `pre` rule if your Markdown has code blocks the sibling CSS lacks.
4. `pip install markdown` if the venv lacks it; then `weasyprint.HTML(filename=abs_html).write_pdf(abs_pdf)`, and the same tofu/CJK-leak/page-count verification as quiz renders.
   - **`**bold**` is NOT interpreted inside fenced ``` code blocks.** Markdown only converts emphasis in *prose*; inside a ` ``` ` block it prints as **literal asterisks** in the PDF. This is the exact trap for the "code blocks for formula steps" usage: a line like `→ 세 직선은 모두 **평행**` inside a formula box rendered as `**평행**` (ch1–2 clean, ch3 요약 shipped this until a fix). Rule: **never put `**` inside ` ``` ` blocks** — write the term plain, or move the emphasis into a prose `>` blockquote / `<p>` outside the fence. Quick scrub if you already wrote some: strip `**` only on lines inside ` ``` ` fences (toggle a `in_fence` flag on lines starting with ` ``` `; don't touch prose bold). Re-render and spot-check the page where the formula box appeared.
- **Parameterized render script beats copy+sed.** For multi-chapter runs, author ONE `render_ch.py` taking argv (`md_path html_path pdf_path footer_label`) and reuse it for every chapter — rather than `cp render_summary.py render_summary_chN.py` + sed-swap. The copy+sed path is one stale `<h1>` or unswapped path away from a broken render (see `scanned-doc-study-notes` stale-title pitfall). Only the footer label + output names change per chapter. (Used successfully for ch1 + ch2 of one textbook without rewriting the script.)
- Naming convention for this user's textbook set: final PDF `천재_<과목><등급>_<단원>_<주제>_요약.pdf`, intermediates `<ch>_요약.md` / `<ch>_요약.html`, **all in the SAME dir as the final PDF** (user explicitly wants intermediates kept, not deleted).
- **Content is usually vision-transcribed from a downscaled textbook-image page (≈600px). Fine-grained fields are NOT reliably readable at that size** — short URLs, QR-code payloads, small CJK publisher/product names, dense per-page source lists. Do **NOT transcribe them verbatim** (you will fabricate plausible-but-wrong chars). Capture only the confident structure (domains, section layout, counts) and mark the rest explicitly `"세부는 교과서 p.X 원문 참조"` / `"축소 이미지 기반이라 오독 가능"`. The summary stays honest and useful; the fabrication risk is what this rule kills.
- Verify one page via `get_pixmap` PNG + vision check for a study summary (no answer boxes to measure — check for tofu, table rendering, superscript/math glyphs).

## Prerequisites
- venv with `weasyprint` + `pymupdf` + Noto CJK fonts (Linux: `fonts-noto-cjk`). Locate the interpreter dynamically and cache its path (see path pitfalls):
  glob `**/venv/bin/python3` under the service dir, write to `/tmp/venvpy.txt`, run `VP=$(cat /tmp/venvpy.txt); "$VP" script.py`.

## Core Pattern (quiz papers)
- 4-choice options: `.opt { display:flex; flex-wrap:wrap } .o { white-space:nowrap }` so each option breaks as a unit (never mid-option). A stated user preference for this user.
- Answer space: one `<div class="qsubj">` WRAPPER per subjective question containing stem `<p>` + `<div class="sa-space">`, with `.qsubj { page-break-inside: avoid; break-inside: avoid; }` and `.sa-space { min-height: <BOX_PT>pt; }`. The wrapper keeps stem+box on one page (no orphan, no split).
- **`<BOX_PT>` is a user-tuned parameter, not a constant.** This user controls answer-box height and wants it **uniform across ALL chapters** (a per-chapter progression was tried then rejected — confirm the size and apply it everywhere). Their history: 130→260→340→300→**150pt**, so always `clarify` the desired height rather than assuming, and when they say 'make them all the same / halve it', change every chapter.
- Answer key: `#answer-key { page-break-before: always; }` (prints on a separate page).
- `@page { size: A4; margin: 15-18mm; @bottom-right { content: counter(page)" / "counter(pages); } }`.

### Preferred for a SET of quiz papers (multiple chapters): data-driven generation
When producing a **suite of quiz papers for one textbook** (e.g. every chapter 1..N, each 객관식 20 + 주관식 5), don't hand-write each HTML file by chunk and don't copy+patch one chapter over the next. Author the quiz as **data + one shared render module**, then loop:
1. **One shared render module** (`quiz_common.py`) exposing `css(footer)`, small `mc_q / mc_a / sbj_q / sbj_a` builders, and a single `render(title, footer, rng, MC, SBJ, html, pdf)` that emits the front (questions) + `#answer-key` (정답표 + 해설) and returns `(pages, tofu)`. Data shapes: **MC = `(num, question, [4 options], ans(1-4), expl, wrong-answer-note)`; SBJ = `(num, question, [expl_lines])`**. Only the per-chapter data block differs; CSS/build logic is shared. This is the "parameterized script beats copy+sed" principle applied to the quiz class.
2. **One driver script holds all chapter data** (`C1_MC, C1_SBJ, …`) and loops `render()`. Single source of truth ⇒ each chapter's **answer key stays consistent with its questions** (kills the classic hand-written-answer-key drift). The 정답표 is built *from* the `ans` field (index `MC[i-1][3]`), never hand-typed — a hand-typed row is where the wrong-answer table gets out of sync.
3. **Validate with `ast` BEFORE any weasyprint call** (cheap): for each MC row assert `len(options)==4` and `ans in 1..4`; assert numbering is contiguous (객관식 1..20, 주관식 21..25). This catches the two real bugs fast: an off-by-one in the 정답표 indexing, and a bad answer constant. (Both appeared and were caught pre-render in a 125-question set.) **`ast` checks STRUCTURE only, not correctness** — for math papers it does NOT tell you the answer is actually right. Hand-derive every `correct` answer AND re-read each 오답정리 to confirm the distractor letters (①②③④) match the real option list before rendering: a wrong `ans` index and a mismatched distractor note both pass `ast` and only surface at the vision spot-check. (A 4장 rounds 2·3·4·5 batch shipped ~6 such errors — isosceles base-angle arithmetic, exterior/interior point location, trapezoid base-angle, 30°/45° side ratios — all caught by re-solving, none by `ast`.)
4. **This sidesteps the write_file CJK-truncation workaround** — the whole chapter's CJK lives in one Python file that writes its own HTML, so you don't fight the small-content limit at all. Keep the chunk-assembly fallback below only as a last resort.
5. **Structure convention for this user** (their reference set is the `중학과학` folder): **front = problems only** (header meta carries 대상·범위·시간 + 구성 + a 채점 기준 line, then `I. 객관식 (20문항)` with `.opt-list` ①②③④, then `II. 주관식 (5문항)` each with `.sa-space`); **back = `#answer-key { page-break-before: always }`** holding a compact **객관식 정답표** (one `<table>` row 1..20 with the circled answer), then `II. 정답 및 해설 (객관식)` + `III. … (주관식)` with per-item 정답/해설 and **오답 정리 in red**. Confirm the front/back split — students must never see the 해설 before answering.
6. Same per-render verify (tofu=0, CJK-leak=0) + one vision spot-check of a front page and of the answer-key page as the quiz core pattern below.

### Enforce the ①②③④ distribution BEFORE rendering (all papers, all rounds)
Balanced-position is a standing requirement for **every** quiz paper in this user's set (not only repeat sets): the correct-answer positions must distribute ~evenly across ①②③④ (e.g. 5/5/5/5 for a 20-question paper). The cheap, reliable guard:
1. After assembling the HTML (or after the data-driven build), parse the answer-key section and count the `정답: <span class="correct">①</span>` badges with a tolerant pattern — the period after the question number is **OPTIONAL** (`?\.`), because `qnum` span markup varies across rounds (`5</span>` vs `5.</span>`) and a strict `\.` silently matches nothing: `python -c "import re, collections; t=open(html,encoding='utf-8').read(); print(collections.Counter(a for n,a in re.findall(r'qnum>(\d+)?\.</span>\s*정답:\s*<span class="correct">([①②③④])', t) if int(n)<=20))"`. **A zero-match count is a CHECK FAILURE, not a pass** — a balance claim backed by a scan that matched nothing is indistinguishable from never checking; on 0 matches fix the pattern and re-run, and do not render until the scan total is exactly 20 (5/5/5/5).
2. If distribution is off (one slot is 6+ and one slot is ≤4, or any ①-heavy skew), patch the **stem options** (move the correct option text to the target slot, keep distractors in relative order, relabel ①-④) AND the `정답:` badge for that question together. Do NOT patch the badge alone without moving the option.
3. Re-scan to confirm 5/5/5/5 before any weasyprint render — the scan total MUST be **n=20**; a 0 or partial count means the pattern didn't match the actual markup (see the zero-match rule above) and the render must wait.
4. **Reorder → renumber 해설:** if you moved any option in that question, grep the matching answer-key 해설/오답정리 for ①②③④ references and renumber them to the new positions (the explanation cites the distractor by position, so a move invalidates every cited letter in that explanation). This is the same rule the repeat-set section already carries, applied here so the FIRST paper (문제_01) doesn't ship ①-heavy.

### Repeat-study variant sets (`_02`, `_03`, …) — this user's request pattern
This user asks for a **fresh paper of the same chapter** to re-study repeatedly ("다시 생성해줘. 파일명은 끝에 _02 로 해 주고. 여러번 반복해서 학습하려고 하거든"). Rules:
- Same scope, **new question stems** — re-derive from the chapter `요약.md`; don't just re-shuffle the existing paper. Name `chN_문제_02.pdf` (+ `.html`) in the same output dir.
- **User explicitly wants the ①②③④ correct-answer positions shuffled/randomized** for these sets. Naive `random.choice` per question is NOT acceptable — one real run landed **11 of 20 on ③** and had to be redone. Use a **balanced pool**: `pool = [1,2,3,4]*(N/4)` (5 of each for 20 questions), shuffle the pool, assign one position per question. Verify the final distribution is exactly ①5/②5/③5/④5 before rendering.
- **Single-source shuffle:** keep `pos = {qnum: slot}` in memory; rebuild BOTH the option spans (correct option text moved to `pos[n]`, distractors keep relative order, all 4 relabeled ①②③④ in place order) **and the 정답표 table** from that same dict in one script — never hand-edit the key table after shuffling (classic drift). **Reordering options invalidates the 해설's distractor letters too.** The free-prose 해설/오답정리 cites ①②③④ *by position*, so it is a THIRD coupled artifact the dict does not rebuild — when you move any option, re-number every ①/②/③/④ reference inside the matching explanation, not just the correct badge. This applies to a HAND-WRITTEN first paper (문제_01, not just _02+ repeat sets) too: after balancing ①②③④ to 5/5/5/5, grep the answer-key section and confirm each 해설's distractor letters still point at the distractors that are actually in those positions.
- **CSS head recovery:** if `/tmp/*_head.html` (and even `/tmp/venvpy.txt`) are gone from a previous session, extract the head from the saved `chN_문제_01.html` by slicing at `<div id="test-header">` — and re-locate the venv by searching `**/venv/bin/python3` with a `import weasyprint, fitz` gate (worked: `services/scrp_pdf/work/venv`), rewrite `/tmp/venvpy.txt`.
- **Batch multi-round (e.g. rounds 3·4·5 in one request):** use ONE parameterized generator (`argv: round_no label`, per-round data module imported via `importlib.import_module('ch3_r%d' % n)`) that does everything per round: balanced `pos` assignment (`random.seed(1000+round)` keeps each round stable), option-span rebuild, 정답표 rebuild from the same dict, render + verify inside the venv, then a single save loop (`shutil.copy2` to `chN_문제_0{round}.pdf/.html`). Per-round subjective answers live in the generator keyed by round number. Do NOT hand-write three HTML files — the generator guarantees the balanced-distribution, CJK, and key-consistency checks run for every round identically. (Worked for 3장 rounds 3/4/5: all 5-page, 80 option spans, subj boxes 5/round, CJK/tofu 0.)
- **Correct-index convention — real batch bug:** when one generator consumes per-round data files authored at different times, the correct-answer field may have been written as 0-based index-into-opts in one file and 1-based position in another. With 4 options the value 3 is *valid under both* conventions, so the mismatch is silent for some questions and `IndexError: list index out of range` (or a wrong choice placed as the 'correct' one) for others. Standardize every data file's correct field to **0-based index into the option list** and assert `0 <= ci <= 3` before building. This broke a rounds 3/4/5 batch run and was fixed by rewriting the 1-based file to 0-based.

### Geometry-figure variant (inline SVG figures on math papers)
For geometry chapters (triangles, parallelograms, squares / isosceles-trapezoids) this user asks to **draw the figures into the paper** ("필요하면 도형을 문제에 그려서 넣어줘"). Inline **SVG renders cleanly in weasyprint** — vector, no tofu, no rasterization — so this works. A working helper-module skeleton is in `references/svg-figures.md`. Pattern:
- **One figure-helper module** (e.g. `figs_ch4.py`) with tiny builders: `_pt`, `_lab(x,y,txt,big,fill,anchor)`, `_arc(vertex,deg1,deg2,r,sweep)` for angle arcs, `_ra(vertex,u1,u2)` for the right-angle square, `_tri`/`_quad` for filled shapes, `_ptc` for vertex dots, `_fig(inner)` wrapping one `<svg>` (`width:100%;height:90`, light bg + border). `fig_block()` emits one flex row per figure: `<div style="flex:0 0 230px">SVG</div><div>도 1. caption</div>`, each `page-break-inside: avoid`.
- **Insert a "참고 도형 (도 1–9)" section in the FRONT** (after `I. 객관식`, before `II. 주관식`) so students see the figures beside the problems that cite them with `[도 N]`. Reuse the SAME `fig_block()` across every round-set of the chapter by importing the module (`import figs_ch4; figs_ch4.fig_block()`) — figures are shared, only the per-round question data differs.
- **Every SVG `<text>` MUST carry an explicit CJK font** — set `font-family="Noto Sans CJK KR,sans-serif"` on each label, else weasyprint's fallback can mis-render the vertex letters (A·B·C).
- **Right-angle square size (s param in `_ra`)**: the default `s=9` is too small at 240×150 viewBox — the square is barely legible on a printed page. **This user explicitly asked for it bigger** ("크기 올려서 다시 만들어줘"). Use `s=16, stroke-width=1.8` (≈2× larger, clearly visible). When retrofitting an existing figure HTML: recompute the 3 path points with `u1*16` and `u2*16` instead of `*9`, and replace `#8a4b0b" stroke-width="1.2"` → `1.8`. All 3 right-angle figures (도 2, 6, 9) need the update.
- **CRITICAL: SVG geometry is NOT in the PDF text layer.** `get_text()` finds the CAPTION ("도 1. 이등변삼각형…") but not the drawn lines/angles, so text-search + `verify_layout.py` report all-clear even when a figure is blank/malformed. Figures MUST be verified **visually**: `get_pixmap(dpi≈110)` + vision — confirm each shape, the vertex labels, the angle arcs, and the right-angle square actually exist. (Locate the figure page by searching its CAPTION text, not the geometry — the SVG itself is text-invisible.)
- Helper bugs that cost re-renders this session: `_pt` must be called consistently as `_pt(A[0],A[1])`, NOT `_pt(A)` (a tuple-vs-two-args mix raises `TypeError`); and a stray `"+"_""` join left a literal `_` between the vertex dot and its label (`_ptc(A)+"_"+_lab(...)`) — strip it before render.

## CRITICAL PITFALL: sibling vs descendant selector (the silent killer)
If the answer box is a **sibling** of the stem `<p class="q">`, the rule MUST be **`.sa-space { ... }`** (plain), NOT `.q .sa-space { ... }`. The descendant form matches nothing, so `min-height` is silently dropped and the box renders ~20pt tall — yet the document still "looks" right in a text dump. **Always verify with a box-height measurement, never by trusting the rule exists in the HTML.** This exact bug shipped in 4 real quiz chapters before measurement caught it.

## Verification (every render)
Run `scripts/verify_layout.py <pdf> [min_box_pt]`: page count, tofu count, CJK-leak chars, and per-page tall drawn-rect heights (the answer boxes). Missing box = no rect in the expected height band.

## Tooling pitfalls (workarounds that work)
1. **`write_file` truncates long CJK content mid-line** (around ~1-2KB of Korean). Don't fight it: write the document as **multiple small chunk files** (CSS header, questions 1-10, 11-20, subjective, answer key), each well under the limit, then **assemble with a Python script** in a fixed order. *Recent sessions have, however, written ~24KB CJK-heavy files in a single write without any truncation — so for a quiz set prefer the data-driven build (above) first, and drop to chunk-assembly only if a truncation actually occurs.*
2. **Korean absolute paths in tool-call args silently truncate/corrupt** (write_file/read_file/patch/terminal). Build paths in Python via `os.path.expanduser('~')` + `os.path.join(...)` or `glob`, then `shutil.copy2` from an ASCII source (`/tmp/...`). Never type the full Korean path inside a tool-call string.
3. **pymupdf drawings API**: use `dr["rect"]` (dict), not `dr.rect` (AttributeError). Filter `if dr["rect"].width > W and dr["rect"].height > H` to find the large boxes.
4. **venv python via cached path file**: `VP=$(cat /tmp/venvpy.txt); "$VP" /tmp/script.py`.
5. **Batch re-sizing a CSS value across multiple files: match BOTH whitespace variants.** Files built in different sessions can carry the SAME value with different spacing (`min-height: 300pt` vs `min-height:300pt`), so a literal `str.replace("min-height: 300pt", ...)` **silently skips** the no-space ones (this actually happened to 1 of 6 chapters). Use a regex `re.sub(r"min-height:\s*300\s*pt", ...)` and, after the write, grep every file back to confirm the new value landed in all of them.

## Procedure
1. Locate venv python → cache to `/tmp/venvpy.txt`.
2. Build HTML in `/tmp` (ASCII dir) as small chunks; assemble in a fixed order with a Python script.
3. CJK-leak check on the HTML: regex `[\u4e00-\u9fff\u3040-\u30ff\u3400-\u4dbf]`, but **scan with context** (`python -c` over `re.findall(r'.{4}[\u4e00-\u9fff].{4}', t)`) so each hit shows ~4 surrounding chars and you can tell deliberate from leaked. **Korean textbook/quiz prose legitimately contains pedagogical Hanja parentheticals — 정(情), 부(父), 수난(受難), 청중(聽衆) — and those are correct; do not strip them.** 'Clean' means *0 Hanja outside your deliberate annotation set*, not a literal 0 (a naive 'fix to 0' will delete correct content or stall on a scan that never reaches 0). The accidental kind to rewrite to Korean is stray **Chinese vocabulary/simplified-Hanja** that leaked in from the composing LLM — e.g. 好处, 实际, 进程, 战争, 人 — fix those only, then re-scan to confirm only the intended set remains.
4. Render: `VP=$(cat /tmp/venvpy.txt); "$VP" -c "from weasyprint import HTML; HTML(filename='/tmp/x.html').write_pdf('/tmp/x.pdf')"`.
5. Verify with `scripts/verify_layout.py` (boxes at expected height, 0 tofu, 0 CJK leak, answer-key page, no split boxes).
6. Copy to the real Korean output dir via Python `shutil.copy2` (path built with `os.path.join`).
7. Spot-check one subjective page via pymupdf `get_pixmap` PNG if box layout is the crux.

## Verification
`verify_layout.py` reports `tofu=0`, `cjk_leak=None`, expected box height on subjective pages, answer-key on its own page. If a page that should have a box shows `boxes=[]`, the sibling/descendant selector bug is live — check the CSS rule.
